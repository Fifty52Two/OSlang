Goal. Run Experiment E1 — ask an AI to generate an EBNF grammar for OSlang from a one-paragraph description, then compare it against our locked grammar.
Prompt. "I am designing a domain-specific language called OSlang for OS simulation. Here is a one-paragraph description: OSlang is a DSL for declaring operating-system concepts — processes, semaphores, and schedulers — and simulating their execution. A program declares named processes with burst time, priority, and arrival time as named parameters. Semaphores are declared with an initial integer value. A system groups processes and assigns a built-in scheduler (FCFS, SJF, RR, PRIORITY). The run statement executes the simulation. The language has if/elif/else conditionals, while loops, user-defined functions with typed parameters and return types, and a print statement. Assignment uses the <- operator. Statement terminator is semicolon. Generate a complete EBNF grammar for this language."
Response (key part). Gemini produced a full grammar with a proper expression hierarchy (LogicalOrExpr → LogicalAndExpr → EqualityExpr → RelationalExpr → AdditiveExpr → MultiplicativeExpr → UnaryExpr → PrimaryExpr), correct if/elif/else and while syntax, and correct semaphore declaration syntax. The expression hierarchy used the iterative { op term } pattern throughout, which correctly encodes left-associativity.
Accepted. The expression precedence hierarchy — Gemini independently produced the same layered structure we locked in Round 4 (§5.12), with the correct operator groupings at each level. The iterative pattern giving left-associativity matches our decision (§5.13). The if/elif/else and while syntax matched our locked constructs exactly.
Rejected / modified. Five significant errors found:
Error 1 — ProcessDecl: Gemini made all three parameters mandatory and hard-coded their order. Our decision (§5.15) is that burst is mandatory, priority and arrival are optional, and order is flexible. Gemini also used burst_time and arrival_time as keywords instead of our locked burst and arrival.
Error 2 — ProcessDecl missing body: Gemini's process declaration ends with a semicolon — no body block at all. Our locked syntax requires a mandatory { } body block after the parameter list.
Error 3 — SystemDecl wrong syntax: Gemini produced a block-style system declaration with { } braces. Our locked syntax is single-line with named fields in parentheses: system Sys1(processes: [P1, P2], scheduler: RR(quant: 2));. Gemini also listed only 4 schedulers (FCFS, SJF, RR, PRIORITY) — we locked 6 (SRTF and MLFQ missing). Scheduler parameters like RR(quant: 2) were completely absent.
Error 4 — FunctionDecl uses def keyword: Gemini used def, imported from Python convention. Our locked keyword is func.
Error 5 — RunStmt missing until parameter and wrong style: Gemini produced run Identifier; as a keyword-statement. Our locked syntax is function-call style run(Sys1); with an optional until parameter: run(Sys1, until: 20);.
Errors caught. All five errors above trace directly to design decisions that cannot be inferred from a one-paragraph description — they required explicit decisions across multiple sessions. The expression hierarchy was the one area Gemini got right mechanically, because precedence rules follow a standard pattern. Everything involving our specific keyword choices, optional vs mandatory parameters, and syntax style was wrong.
Reflection. The E1 experiment confirmed a clear pattern: AI generates the mechanical parts of a grammar correctly (expression precedence, operator groupings) but fails on the parts that encode deliberate design decisions (keyword names, optional parameters, syntax style). This is because those decisions live in our session history, not in a paragraph description. A grammar is not just a syntax description — it is a record of design choices, and those choices are invisible to an AI that was not present when they were made.
